api.found computes canonical definition/intent seed and scopeID, routes to the
same env.NET object's native found method, which rechecks seed/definition,

calls this SAMEapi after URL/method/raw-body/shape decoding, adds JSON answer
and status201; clienthttp adds encoding/untrusted-answer/timeout/size parsing.
Thus api transport is a genuine in-isolate service boundary, NOT a mock and
NOT an HTTP route. Calling route(newRequest,env.NET) would retain route parsing
without SELF, but still performs wire serialization. Non-wire lane invariants
need neither transport crossing nor repeated body-parser proof.
