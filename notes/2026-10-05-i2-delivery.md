# I2 base milestone: the lane forms as data, on the scope substrate

Request `efb4e323`. Branch `request/i2-lane-forms`. Written 2026-10-05.

**This is a milestone of I2. It is not I2.** The planner has ruled that
the base may be reviewed and may land while the request stays open. The
commission says that partial base work "cannot satisfy the full I2
delivery". Section 4 lists the rows that remain and whom each waits on.
This note is the producer's account. An independent review decides what
it is worth.

## 1. What is delivered, first

1. **The two lane definitions, `issue` and `change`, as data**, in a new
   package, `packages/lanes`. Each passes `validateDefinition` whole at the
   bounds of `PROPOSED_BOUNDS`, and each is pinned.
2. **The forms of the adopted scope contract that the two definitions use
   and that I1 did not have**: 38 forms, in `contract`, `bytes`, `derive`,
   `scope`, `replay` and `client` (section 3).
3. **A client handle that is typed from any declared definition**
   (`declaredHandle`, in `packages/client`).
4. **Ten scenarios** that run the two pinned definitions on real scopes,
   with stand-ins that each test names (section 7).
5. **Removal and guides**: one parked file deleted, the ledger reconciled,
   `docs/lanes.md` and a generated `docs/lanes-reference.md` (section 9).

**Under the production wiring, nothing of the lanes runs.** A scope is not
founded or created under either definition. The answer is
`unsupported-definition`. That is the design, for this reason. Both
definitions list `git-read@1` and write guards and effects of `hold@1` and
`git-read@1`. The contract's section 6.1 says that a runtime which does
not implement a capability version "answers `unsupported-definition` and
admits nothing to that scope". No code for those capabilities exists: the
authority note's successor (request `406983fe`) owns their rules and I3
builds them. A runtime that ran the other rows and skipped the capability
rows would write entries that a later, complete runtime would judge
otherwise. So the whole scope is refused, and the verifier answers the
same at the genesis. Witness: `packages/scope/test/founding.test.ts`, "a
definition that needs a capability record". This is the builder's
decision on an open question (deltas entry DJ14). The owners have not
confirmed it.

- **At step 16: 21 controls, 17 distinguished, 4 survived** (the worker's

branch adds 71 tests in vitest and 1 script check. The estimate was
