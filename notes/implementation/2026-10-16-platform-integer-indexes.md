## Section 17.2a amendment

A platform item type may index a fixed, required `int` slot, as it already
may index `fact`, `item`, `scope`, `member`, `digest`, `commit` and `tree`
slots. The existing one-to-four distinct-slot limit remains. Declared
definitions cannot state `indexes`.

An integer key is its existing canonical JSON number: unquoted signed
decimal text, with zero spelled `0`. The slot's safe integer min/max still
apply; negative values and zero are permitted when its declaration allows
them. There is no alternate encoder, numeric ordering, range query or
uniqueness guarantee. A string `"1"` and integer `1` have different keys.
A selector's required field must still match its indexed slot's exact
type, including the integer range.

Lookup keeps the current item-type/slot/key identity and bounded results
in item-ID order. Several live or final items may share a key. Incomplete
indexes still refuse lookup. Folding writes rows when items open;
finality leaves them present, and fixed slots cannot change. Re-folding
and rebuilding from checkpoint items derive the same rows. Checkpoints
gain no index payload.

The additive validation change needs no separate integer wire tag. A
future platform cohort that uses it must have its own immutable supported
name/version. This slice changes no existing platform data or pins and
activates no new directory or partition. C1 standing reservations, A1
dropped advisories and D1 destination key standing remain separate
prerequisites of the [partition design](../2026-10-15-directory-partitions.md#10-prerequisites-owed).
