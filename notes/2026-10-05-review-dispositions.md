## How to read a row

- **Finding**: the review's claim, in one line.
- **Verdict**: `Agree`, `Partly`, `Disagree` or `Not confirmed`, then the
  reason as read from the code, with file and line. A line number that
  differs from the review's is given as found.
- **Route**: one of four.
  - `Design`: a named section already answers the finding.
  - `Design, owed`: the named section does not yet answer it. The row says
    what is to be added, and where. Every such row is listed again in
    "Owed in design this sprint".
  - `Fix`: a change to the current product, listed in "Proposed fix batch"
    and not made here.
  - `Accepted`: no change, with the reason.
  A row with `Design` or `Design, owed` may also name a fix, as "Also F1".
- **Owner**: who acts next. The planner holds the design requests, so a
  revision of a design note is shown as the planner's, and the build as the
  delivery that carries it. The builder owns I1.

Two facts shape the routes. The earlier packages are parked on the I1 branch
and are replaced, not repaired. The deployed spike and the packed
`0.1.0-dev.1` release run the earlier code at `b6a9c0b6` until E1 retires
them. The spike is a development deployment that holds one kept
demonstration room.
