# I1 story: create, relate, replay

2026-10-05. Measurement: observed run, one process, in-process storage
double. Node v26.10.0. Source: main at f1c456ce6 (I1 as landed).

## What this shows

This note shows what the scope substrate under `packages/` does today, by
one run of its real code. A desk creates a ticket, and the ticket is
provisional until the desk confirms it. One ticket then sends two
relationship updates to another, and a request to its desk, and each
request gets one result back. Last, the replay command reads one ticket's
retained history and derives every entry again. Every message between
scopes is carried by the outbox dispatchers. The script only submits
signed intents, reads, and moves the clock.

## How to run it

The transcript below is from the I1 source at commit `f1c456ce`; later source prints different identifiers.

```sh
npm ci
node notes/2026-10-05-07-i1-story/run.mjs
```

The run takes under a second. It uses no network and deploys nothing. Two
runs printed the same 70 lines, byte for byte (SHA-256 `9211becd2b4b`).

## What each step shows

- **Step 0.** A person founds a directory by a signed intent. The client
  package signs it and posts it to the Worker's route. The scope's ID is
  the digest of its seed.
- **Step 1, creation.** One act, `open-issue`, writes `D.1` and its
  `create` send in one commit. The ticket writes its genesis `P.0` and is
  provisional. Its result goes back and `D.2` records it. While the
  confirmation is held back, `P` answers an act `unavailable`, with the
  reason `scope-provisional`, and keeps its own advisory send held.
- **Step 1, confirmation.** One second later the dispatcher of `D` sends
  the confirmation again. Its log reads `none, acknowledged`: one attempt
  with no answer, then one that `P.1` recorded. `P` is then active, and
  its held send goes out and becomes `D.3`.
- **Step 2a, relationship updates.** `P` owns a link and tells `I` its
  state with a `relate` send. `I` keeps a copy whose revision is the
  position of the owner's entry: 2 for `set`, then 4 for `removed`. Each
  update gets the result `applied`, which `P` records as `P.3` and `P.5`.
- **Step 2b, a tell.** `P` sends the desk a `tell`. The handler of `D`
  applies it in `D.7` and sends a result. `P.7` records the result and
  runs the `applied` clause, which moves item 6 from `asked` to
  `answered`.
- **Step 3, replay.** The replay command reads the stored bytes of `P`
  through the read routes. It folds the history from the genesis and
  compares each derived entry with the stored one. The history of `P`
  uses 12 facts of other scopes. To show them, the command also replays
  `D` through entry 7 and `I` through entry 3. The result is `consistent`, and the
  report lists what it took on trust.

## What it does not show

- **Not a deployed Worker.** The script stands in for three parts of the
  Cloudflare runtime: the base classes of `cloudflare:workers`, a Durable
  Object's state, and the namespace binding. Storage is `node:sqlite` in
  memory, one database for each scope. The routes are called in the
  process, with no network. The package tests run the same classes in
  workerd, on Durable Object storage; this run does not.
- **No restart and no alarm.** The double stores the alarm time and never
  fires it. The script calls each dispatcher after it moves the clock.
  Nothing is evicted, so recovery after a restart is not shown.
- **No real authority.** The authority port calls every grant current,
  and the readers port lets every reader read. The grants come from
  derive's test fixtures and name a membership scope that does not exist.
  The production defaults refuse both.
- **No signature custody by a real device.** The keys are fixed test
  secrets from derive's fixtures. The signatures are real Ed25519
  signatures and the scopes check them.
- **A fixed clock and fixed incarnations.** The clock is one value that
  the script moves. Each incarnation is derived from the scope's name, so
  that two runs print the same bytes. A deployed scope mints it at random.
- **Transpiled by esbuild.** Node cannot strip the types of the scope
  package: `packages/scope/src/turn.ts` has one parameter property. The
  script transpiles each `.ts` file with the esbuild that `npm ci`
  installs with the scope package's test tools. No package declares it.
- **Only the good path.** The run has no refused act, no deadline, no
  diagnosis of an undelivered request, no update that arrives out of
  order, no checkpoint and no replay that ends in a mismatch. The package
  tests cover these. This run does not.
- **The third ticket is not followed.** Step 2b makes the desk create
  one more ticket. The run counts it and does not read it.
- **Helpers from test files.** The definitions, keys and grants are
  imported from `@generalbusiness/artroom-derive/testing`, which the
  derive package exports from `test/fixtures.ts`. Everything else is
  imported from the packages' public exports.
