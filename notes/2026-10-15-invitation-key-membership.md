## The new credential protocol

The explicitly selected `invitation-key` cohort uses register@10,
directory@9 and membership@6, with application rules@3, destination@2 and
inbox@1. All names carry the `platform:` prefix. The application factory
and its grants remain the application cohort's. Existing defaults and the
application, file-publication, Counting and demo cohorts keep their pins.

An invitation records `inviteKey`, the Ed25519 public key of a private
32-byte invitation seed, and its expiry. Person links and tagged agent-key
links carry that seed privately. The new join/enrol fields contain only
`invitation` and `proof`. The invitation key signs canonical bytes of the
full membership ScopeRef, invitation item ID and joining KeyId, under
`artroom-invitation-proof-1`. Scope incarnation, invitation and joining key
are all bound. A signature for one cannot authorize another.

Membership verifies that proof before binding the invited member/key.
The existing used/expired invitation, recovery-key, key-reuse, controller
and member-state checks remain. Legacy versions keep their original
inviteHash/secret fields and rules. The new declaration rejects a secret
field; the native serving guard also refuses that legacy form before it
can be recorded. It verifies outer size, shape and joining-key signature
before reading the pinned cohort to select the credential form. Existing
rate and waiting limits still apply.

The SDK supplies one issuer/redemption helper. CLI direct and retained
issuance, person join, independent agent enrollment, local MCP join,
hosted-agent enrollment and Page join use it. Exact original request,
key, deadline and accepted-fact custody remain separate from the private
invitation seed. The Page retains its exact signed proof across reload.
The CLI's explicit selected installation uses existing planned custody.

The new cohort's data digests are pinned in the existing version witness.
Every existing golden digest stays unchanged. New version6 native authority
and read-session issuance use their own exact pin, rather than aliasing an
older membership definition. The Page bundle and MCP tool reference are
regenerated by their existing producers.
