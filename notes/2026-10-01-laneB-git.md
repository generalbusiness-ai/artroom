# Lane B: the git engine and the landing operation

2026-10-01. The package is [packages/git](../packages/git/README.md)
(`@generalbusiness/artroom-git`). It builds on the lane 0 contract, with the
repair for review `45431cd9` and the amendment approved as `955741de`, and on
the approved Sandbox spike ([spikes/sandbox-git](../spikes/sandbox-git/README.md)).

## What it does

- **Workspaces.** One Artifacts fork per lane. One write token per lease
  generation, scoped to the fork, expiring with the lease, and revoked on
  release, expiry or take-over. The public operation view never holds the
  token (R-WS-1).
- **Pinning.** A proposed head's objects are copied into the canonical repo,
  and the head is pinned at `refs/artroom/heads/<lane>/<generation>`, which
  never moves (R-PROP-1, R-PROP-2).
- **Path diffs.** Through the Artifacts binding: bounded, cached by tree
  hash, from the merge base, with old and new paths for renames
  (R-PROP-3, R-PROP-6).
- **Previews.** In the publisher sandbox, only when the proposal and main
  touch the same paths (R-PROP-7).
- **The landing operation.** Plan section 8: a durable record in SQLite,
  parallel preparation, reservation in one synchronous transaction, one
  publication slot, a 60-second token per push, complete-forward recovery,
  abort attempts, and crash recovery by the alarm. Nothing is released on
  elapsed time.
- **The publisher container.** git only, hardened (hooks off, no repository
  attributes, bare repositories, no internet). Its only way out is a gateway
  that adds each operation's token and lets a push through only if every ref
  update is the one that operation allows.

**Mutation checks.** Ten guards in the landing core were broken one at a
time. Eight made landing tests fail at once. Two (pushing despite an abort,
pushing against another writer) survived, because the driver's read-back
step shadowed the core's guard. Core-level tests now cover those guards
directly, and both mutants fail them. The three guards added for the
land-input amendment were checked the same way, and each made a test fail.

## Not done

- **The product Room.** Lane A hosts this package. The harness Room stands
  in: every lane it is told about is held, and there is no policy.
- **Checks.** Readiness is the Room's answer; real checkers are lane G.
- **Rename detection with edits.** Renames are exact; a rename with edits
  shows as a deletion and an addition (both paths are listed).
- **Batching** several ready operations into one integration (optional in
  the plan).
- **Live crash tests against the real container.** Crash recovery was
  tested in Node (real git) and in workerd (real Durable Object storage,
  alarms and instance aborts), with a fake remote in workerd. Live, the
  alarm path ran without a crash.
- **An admin action for an unresolved publication** (protocol open point
  16): none exists; admins can see it.
