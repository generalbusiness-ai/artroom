# Versioned native creation context

Owner decision `aba0fe556ebb6574ff79eebd4e6c3c0b5680282e` selects this bounded
F1 extension to the native creation contract. Source preparation is authorized;
native acceptance, final gate, formal Source review and landing remain owed.

An application created by the explicit supporting directory@5 carries reserved
native body metadata `creationContext: {v: 1}`. The object has exactly one own
member, `v`, with numeric value1. The separate existing `body.membership` holds
the actual confirmed full membership reference, including its incarnation.
The marker carries no duplicate member claim, credentials, permission or grant.
Directory@5's native application rule emits both from its judged parent context.
Neither outer intent fields nor domain `body.fields` can select or replace them.
A domain field named `creationContext` remains ordinary schema-checked data.

After its existing parent/source/message/seed/cause proof, the genesis judge
refuses an unknown/malformed marker or a marked missing/invalid full membership
with the existing `bad-field` refusal. A refused genesis records only its native
result; it emits no declared child request. Valid marker validation does not
replace schema, source, grant, closure or resource checks.

For an applicable declared child creation, version1 forwards the marker and
that SAME verified full membership through the parent genesis and subsequent
declared creation edges. During genesis the existing `Judging.judged` input
holds the incoming verified create. On later turns the existing `own(0)` reader
holds the immutable sealed genesis input. Both runtime and replay use those
same inputs. No new Core port, network lookup, private storage read, mutable
cache, signer field or domain MemberRef supplies this context. Missing own
history retains the existing unavailable behavior; no authority is invented.

Forwarding applies to declared non-membership scopes and declared non-membership
targets. It does not stamp platform siblings or membership-self/target cases.
Platform directory genesis still has no confirmed full membership while it
creates its siblings. Rules and destination keep their membership scope-ID
fields and existing later incarnation/observation/session preparation. Existing
ordinary later-create membership behavior remains intact when no marker exists.

Absence is LEGACY mode. Its native sends and replay derivation remain exactly
as before, including the historical absence of membership from a declared
genesis create. Existing stored duties retain their original bytes/identities;
this change regenerates or migrates none. Old unbound descendants are not
retroactively ready. Unknown marker versions are refused rather than downgraded
or treated as an unmarked request.

The marker is a fixed scalar protocol object; full references retain existing
shape/type checks. It changes no Counting declaration/pin, field minimum or
maximum, default cohort, effect/send/item count, signature, session window or
grant. All native field counts, strict canonical parsing, entry byte limits,
atomic retention and settlement-duty checks still apply to the complete entry,
including this metadata. An accepted parent and its native duty are not ready
child success; the verified applied result and confirmed full child ref remain
required. Per-invocation limits are not aggregate history/physical-memory proof.

The supporting cohort remains register@5 → directory@5 → membership@4/rules@3/
destination@2/inbox@1. This extension preserves the composed source's existing
defaults: register/directory/destination@3 and membership/rules@2, with inbox@1.
The older register/membership/rules constants remain@2. No old scope or pending
signed request silently selects a newer version. The native fixture must prove the
actual nested Counting child can read with a real room session, obtain its
explicit counting.control grant and Initialize, and that parent/children replay
with the retained creation provenance. Domain configuration and retained bytes
alone are insufficient.
