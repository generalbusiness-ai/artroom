# Platform version preparation

This package now supplies explicit future `@2` data and rules beside the
native `@1` source at commit `0938010b54e27d436ea1feb92dce6e843ac7bf54`.
This is preparation under requests `48407a70` and `9be26ef7`, following
planner adoption `a515f21b5e1f3f3e1fa75c222722a825255fd8fa` of design
`c8318a8a0`. It activates no runtime, register, provider or deployment.

`platform(name)` looks up only an exact entry of `VERSIONS`. Unknown names,
versions and aliases have no supplied implementation. `NEWEST` states the
future install choice separately. Existing public constants, `definitions`
and `RULES` keep their native `@1` meaning; consumers must explicitly adopt
newest install selection rather than change an old scope through an alias.
`isOf` classifies a name; it supplies no code or authority.

The original family modules remain unchanged. The future implementations
are isolated in `src/future-2`, using selected source from donor
`f4859a3d83458653f386ccf20a50457978df1ebd`/`1c63b4db2`. They retain current
Gate1 definition-value places. Native directory/rules `@1` are not restored
to original-main data lacking those places. Native membership's first lists
and observations remain `@1`; the future rule initializes all five roles
with `destination.read-token` and its observation states `@2`. Register and
directory rules derive children and operation owners from their own genesis
pin. Future destination rules add one `mint-read`, with one attempt and no
retry; its reported expiry is not replaced by a client deadline. Its
founding objects include `README.md`; native empty-tree bytes stay unchanged.

The source snapshot in `test/fixtures/native-093-source.json` binds native
module bytes and the previous catalog to that exact commit. The catalog
witness also checks native data/rule references, unknown refusal, whole-data
validation, and selected old/new rule and observation outputs. These are
source-preservation and pure evaluator witnesses. Scripted genesis/state
inputs establish no live `@2` authority, room, credential or clone.

This is not the adopted historical resolver. A legacy name alone cannot
select the actual bundle of a colliding original-main, clone-era or later
`@1` history. The native entry identifies this source profile only; it must
not be promoted into a fallback binding for an unproven legacy room.
Before activation the complete immutable semantic archive must retain
canonical data, actual executable/build bytes and inputs, evaluator ABI,
dependency/toolchain identity, mark/rule and observation/observed-value code,
reference and historical authority derivation, capability versions, and
outside-evidence/credential-handle interpretation. Source hashes and shared
helpers alone are not that archive.

The operator-authenticated service/full-scope/genesis/head/admission-build
binding and independent evaluator/port/schema correspondence review remain
required. Current strict transport/admission guards must remain outside the
historical evaluator. Runtime version selection, historical coverage,
bootstrap access, additive old/new root routing, immutable attempt/provider
bindings and the admission/physical-send closure barrier are not implemented
here. Unknown provenance or unsupported executor correspondence must hold
affected work and preserve records, pending attempts and custody. Complete
compatible activation and actual room-issued cloning remain separate work
under the existing owners.
